Why another CMP

Most consent banners treat Adobe as an afterthought.

That shows up in three places. This one was built the other way around.

Weight

A hosted CMP loads a stub, then a config, then the real SDK — three round trips before a banner can paint. Benchmarks put OneTrust near 184 KB across 16 requests. This is one 14.6 KB file, and as a Launch extension it's inlined into the Tags library: no extra request at all.

Glue code

The usual recipe: override OptanonWrapper(), parse a category string, hand-map it onto adobe.optIn, then write a second mapping for setConsent. Every site reinvents it and it breaks on vendor renames. Here the mapping is configuration and the Adobe calls are the library's job.

Compliance defaults

Only 11.8% of UK top-10k sites using the five biggest CMPs met minimal GDPR consent requirements. Those are configuration failures the products permit. This one doesn't: reject is as prominent as accept, nothing is pre-ticked, Escape never means yes.

The one API worth learning

gate() replaces every “did they consent yet?” branch.

Hand it a category and a callback. It runs now if that category is already granted, and otherwise waits until the visitor grants it — then runs once. Your tag never needs to know about consent state at all.

  • Fires immediately for returning visitors who already agreed
  • Queues cleanly on a first visit, releases on the click
  • Also dispatched as DOM events, so nothing needs to import the library
app.js 
// runs now, or the moment analytics is granted
AdobeConsent.instance.gate('analytics', () => {
  loadAnalytics();
});

// or listen without importing anything
document.addEventListener('adobeConsent:change', (e) => {
  console.log(e.detail.granted, e.detail.revoked);
});

What makes it great with Adobe

Five surfaces, wired on every load and every change.

Each adapter feature-detects its target and does nothing when that product isn't on the page — so leaving all five on is safe. Together they mean a consent decision reaches every corner of an Adobe stack without a line of custom code.

The collect nuance

Adobe enforces Web SDK consent all-or-nothing on collect. So collect maps to the union of your data categories — map it to analytics alone and a visitor who allowed personalization but refused analytics would lose their personalization data too. A subtlety most hand-rolled integrations get wrong.

No phantom adID on web

XDM requires an IDFA/GAID idType next to adID — identifiers that don't exist in a browser. The library omits it on the web and only sends it when a hybrid app names the type. Correct XDM, not a rejected payload.

One CJA dimension

The Consent Summary data element emits essential+analytics|accept_all|EU — a single low-cardinality value. Report consent rate, method mix, and regional split in Customer Journey Analytics from one dimension instead of four.

Region resolver — powered by the real engine

Pick a visitor's region and see the model the library chooses and the exact setConsent payload it would send before any click. This is computed live by the shipped code, not a lookup table.

Compliance posture

These are behaviors, not settings.

The failure rate across the industry is the argument for opinionated defaults. The choices below can't be misconfigured away.

Reject = AcceptSame size, same styling, first layer. The CNIL fines against Google (€150M) and Meta (€60M) turned on exactly this asymmetry.
Nothing pre-tickedIn opt-in regions, per CJEU Planet49. Inactivity and Escape are recorded as a rejection, never as consent.
GPC honored by defaultGlobal Privacy Control is binding under CPRA and Colorado law — the basis of Sephora's $1.2M settlement.
Auditable receiptsEvery decision records id, timestamp, method, region, policy version, the wording shown, and a digest.
Operable dialogrole=dialog, focus trap, focus restore, background inert, reduced-motion and forced-colors support. Zero axe-core violations.
Region-awareOpt-in for the EEA/UK/CH/BR, opt-out for US states and Canada, resolved with specificity matching and no first-paint block.
This is engineering, not legal advice. Your categories, copy, and retention still need a lawyer's eye.

Install

Three ways in.

Recommended path is the Launch extension — you get events, a condition, actions, and data elements with no custom code.

terminal
npm install
npm run build              # produces the vendored bundle
cd launch-extension
npx @adobe/reactor-packager # → package-adobe-consent-1.0.0.zip
npx @adobe/reactor-uploader package-adobe-consent-1.0.0.zip \
  --auth.client-id=... --auth.client-secret=...
index.html
<!-- configure inline; the library auto-inits on load -->
<script src="/adobe-consent.min.js"
        data-adobe-consent
        data-config='{"policyVersion":1,"honorGpc":true}'></script>
app.ts
import { init } from 'adobe-consent';

const consent = init({ policyVersion: 1 });
consent.gate('advertising', () => loadPixel());
